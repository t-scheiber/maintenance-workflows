# Shared public maintenance workflows

This repository holds the public Pages workflow and generic validation tools for the two configured demo sites. Each site keeps one small caller pinned to a reviewed commit in this repository. Repository secrets, application credentials, AI services and private repository inventory are not required here. Public scanner authority is an exact copy of a separately protected control-plane decision, never supplied by a source repository or downloaded archive.

The `static-pages.yml` reusable workflow verifies the caller's exact repository identity, source revision, main branch, event and paired workflow/tool commit before checking out shared tools. `STATIC_PAGES_ENABLED` must be `true`; absence disables deployment. Manual runs require the personal owner. The all-zero revision used in unpublished caller templates is rejected.

Project code and shared tools use separate checkouts. Only shared tools execute on the host. Installation receives sanitized manifests with scripts disabled; project tests, validation and build execute after network disconnection in the exact scanned public Node 22 runtime. A fresh runtime scan must match the reviewed OS and complete language package inventories, exact image configuration and architecture. Missing analysis diagnostics, incomplete inventories, unknown severity, and high or critical findings block execution. Low and medium findings remain visible in the receipt. The separately installed Node binary is covered by immutable build provenance and its checked version, not an invented Trivy package entry.

Four scanner families, full Git history secret scanning, bounded artifacts, deployment revision checks and post-deployment asset verification remain mandatory. Deployment renders an explicit demo with empty provider configuration.

Native source authority binds the successful protected hosted verification run 34043216267 and still requires fresh evidence for every current run. The corrected actionlint 1.7.12 maintenance rebuild is downloaded anonymously from its immutable release and checked against a protected external manifest. A fresh, source-free scan must contain all 13 exact packages and no findings or warnings before the linter receives captured workflow YAML in a nonroot, read-only, network-disabled container. Its compiled core tests passed; unrelated developer-generator tests retain their documented failure, and those generators are not linked into the binary. No deployment is enabled by this tree.

Before source parsing, each job verifies the immutable public scanner bundle, scans the complete transport and all three native binaries, checks current run/source/tools identities, and requires the exact protected native decision. Source scanner runtimes are either the source-free Node 24 recipe or the patched Semgrep recipe, each with fresh complete coverage. Public control tests run in the admitted Node 24 container with network disabled; Python is the distro-owned `/usr/bin/python3`. No source-owned report path is uploaded.

Run `npm test` and `npm run lint` on Linux to verify the dependency-free Node and Python controls. Python uses the standard library. The separate verification workflow checks policy, syntax and scanners on changes. Protect these controls and publish a verified signed commit before replacing both caller pins together. Do not use mutable tags or branches, inherit secrets, weaken required checks or give an automated source fixer authority over this repository.

A reusable workflow can only reduce the caller's token permissions. The caller grants Pages deployment permissions to its reusable job; individual non-deployment jobs reduce permissions to repository read access, and only the deploy job receives Pages and OIDC write access. See [GitHub's reusable workflow documentation](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows).
